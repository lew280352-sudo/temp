# จุดบอด ข้อจำกัด และผลการตรวจ

ประเมินจาก source ของรุ่นนี้ ไม่ใช่การรับรองความปลอดภัยหรือความพร้อมให้บริการสาธารณะ

## แก้ไขแล้วในรอบนี้

| ปัญหา | ผลหลังแก้ | หลักฐานการตรวจ |
| --- | --- | --- |
| แท็บเก่าเขียนทับพอร์ตจากอีกแท็บ | UPDATE ต้องตรง revision ล่าสุด ไม่ตรงคืน 409 แล้ว UI โหลดข้อมูลล่าสุด | API และ browser tests |
| สลับบัญชีในอีกแท็บแล้วส่งข้อมูลบัญชีเดิม | ตรวจ userId จากหน้าเว็บเทียบกับเซสชันก่อนเขียนข้อมูล | API regression test |
| Logout ระหว่างอ่าน body ของคำขอบันทึก | ตรวจเซสชันซ้ำหลังอ่าน body | ตรวจ flow ฝั่ง server; ไม่อ้างว่าทดสอบ race timing ทุกแบบแล้ว |
| รีเฟรชแล้วหลุดจากหน้าปัจจุบัน | กู้หน้าจอจาก hash หลังตรวจเซสชัน | browser test หน้า sources |
| ไม่มีทางสำรองข้อมูล | เพิ่ม export JSON เฉพาะบัญชี และ SQLite backup command | API export และ SQLite backup/restart tests |
| ทดสอบ UI ใช้ Windows path อย่างเดียว | ใช้ Playwright Chromium บน Linux/macOS และ Edge บน Windows | Windows browser tests; Linux CI ต้องดูผลบน GitHub |
| อาจตั้งค่า APP_ORIGIN ผิดหรือเปิด LAN โดยไม่มี origin | ตรวจค่าตอนเริ่มระบบ และให้ตั้ง APP_ORIGIN ก่อน bind นอก loopback | configuration tests |
| ไฟล์ตั้งค่า Sites เก่าอาจติดไป GitHub | ignore `.openai/`, ฐานข้อมูล, backup, secrets, node_modules และ test artifacts | ตรวจรายการ staged ก่อน push |
| ผู้ใช้ 20 คนอยู่ IP เดียวกันสมัครแล้ว Login ไม่ได้ | เปลี่ยนจาก 20 ครั้งรวมต่อ IP เป็น 10 ครั้งต่อบัญชี+IP และ 200 ครั้งรวมต่อ IP ใน 15 นาที | baseline ล้มเหลว 20 บัญชี; หลังแก้ flow ผ่าน 20/20 และ anti-abuse tests ผ่าน |

## ยังไม่พร้อม — งานสำคัญก่อนใช้เงินจริง

| ระดับ | จุดบอด | ผลกระทบ / สิ่งที่ต้องทำต่อ |
| --- | --- | --- |
| สูง | ข่าวและราคาเป็นข้อมูลสาธิต | ใช้วิเคราะห์เงินจริงไม่ได้ ต้องมีผู้ให้บริการข้อมูลและสิทธิ์ใช้งาน พร้อม timestamp/ตลาด/หน่วยเงิน |
| สูง | เปอร์เซ็นต์ AI เป็นค่าตายตัว | ไม่ใช่ความน่าจะเป็นหรือความแม่นยำ ต้องสร้างโมเดล/วิธีประเมินและ backtest ที่ไม่รั่วข้อมูลอนาคต |
| สูง | Custom GPT ยังไม่เชื่อม | ยังไม่มี Instructions/Knowledge/Actions ของ GPT ตัวจริง รวมถึง AI backend ที่ได้รับสิทธิ์ใช้ |
| สูง | URL เป็นรายการที่บันทึกไว้ | ไม่มี crawler, RSS/API ingestion, ตรวจข่าวซ้ำ, สรุปข่าว หรือ scheduler; ไม่ได้ตรวจความจริงของเว็บที่เพิ่ม |
| สูง | ไม่มีการยืนยันอีเมล/กู้รหัสผ่าน | ใครก็กรอกอีเมลที่ยังไม่มีบัญชีได้และผู้ใช้ที่ลืมรหัสผ่านกลับเข้าบัญชีไม่ได้ ต้องเชื่อมบริการอีเมลและ token ที่หมดอายุ |
| กลาง | การแจ้งเตือนบันทึกค่าอย่างเดียว | ยังไม่มี push/email provider, consent flow หรือคิวส่งจริง |
| กลาง | Rate limit เป็น memory ต่อ IP และบัญชี+IP | รองรับกลุ่ม 20 คนในกรณีที่ทดสอบแล้ว แต่ restart ล้างค่าและ proxy/NAT ยังแชร์เพดาน 200 ครั้ง/15 นาที ต้องออกแบบ trusted proxy และ shared limiter ก่อนหลาย instance |
| กลาง | SQLite ไฟล์เดียว | เหมาะกับ single instance ที่มี persistent disk; ต้องวาง backup/restore/monitoring และย้าย DB หากหลาย instance |
| กลาง | ไม่มี import JSON / ลบบัญชี / logout ทุกอุปกรณ์ | export ใช้เก็บข้อมูลได้แต่ยังนำกลับผ่าน UI ไม่ได้; ต้องเพิ่ม lifecycle บัญชีและการจัดการ session |
| กลาง | พอร์ตไม่ใช่บัญชีซื้อขาย | ไม่รองรับรายการซื้อขายจริง ค่าธรรมเนียม ภาษี ปันผล corporate actions หลายสกุลเงิน หรือ realized P&L |
| กลาง | หุ้นค้นหาได้เพียง 6 แห่ง | ต้องเชื่อม master securities และรองรับตลาด/สัญลักษณ์ที่ซ้ำกัน |
| ต่ำ | Font โหลดจาก Google Fonts | หากเครือข่ายปิดกั้นใช้ fallback; พิจารณา self-host font และความเป็นส่วนตัวก่อนเปิดบริการ |
| ต่ำ | โค้ด UI เดิมบางส่วนยาวในบรรทัดเดียว | ควรแยก views/data/events เป็น module เมื่อขยายฟีเจอร์; รอบนี้คงหน้าตาเดิม |

การตรวจ URL ปัจจุบันเป็น validation ของ bookmark เท่านั้น **ไม่ใช่ SSRF defense สำหรับ crawler** หากเพิ่มการดึงเนื้อหาต้องตรวจ DNS, IP ทุกปลายทาง/redirect, จำกัดเวลา/ขนาดไฟล์ และเคารพสิทธิ์เข้าถึงต้นทาง ห้ามนำ validator ปัจจุบันไปอ้างว่าปลอดภัยสำหรับ fetch ทุก URL

## สิ่งที่ต้องมีเพื่อทำงานต่อให้เป็นบริการจริง

1. Instructions/Knowledge และรายการเครื่องมือของ Custom GPT ที่เจ้าของมีสิทธิ์ใช้ (ไม่ส่ง API key ในแชตหรือ Git)
2. ผู้ให้บริการข่าว/ราคา เงื่อนไขสิทธิ์ API และตลาดหุ้นเป้าหมาย
3. โฮสต์ Node.js พร้อม HTTPS, domain, persistent disk, ระบบสำรองและติดตามข้อผิดพลาด
4. ผู้ให้บริการยืนยันอีเมล/กู้รหัสผ่าน และช่องทางแจ้งเตือนที่เลือก
5. เกณฑ์วัดผล AI และวิธีแสดง “ประเมินไม่ได้” เมื่อข้อมูลไม่เพียงพอ

การ push repository เป็นการส่ง source และคู่มือ ไม่ได้ทำให้ส่วนเหล่านี้เชื่อมต่อเอง

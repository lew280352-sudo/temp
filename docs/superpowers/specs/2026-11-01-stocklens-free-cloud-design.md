# StockLens — ปรับหน้าจอและเปิดคลาวด์ฟรี

วันที่: 1 พฤศจิกายน 2026  
สถานะ: ผู้ใช้เลือก Render Free + Turso Free และยอมรับการพักแอปแล้ว; แบบและแผนลงมือฉบับนี้รอตรวจ  
ใช้แทน: 2026-11-01-stocklens-ui-and-docker-design.md

## เป้าหมายและข้อตกลง

ปรับ StockLens เดิมทั้งหน้าจอและการเปิดออนไลน์ ผู้ใช้ไม่ต้องเปิดคอมค้างไว้ และไม่ใช้บริการเสียเงิน ไม่ซื้อโดเมน ไม่เปิด billing/overages หรืออัปเกรดอัตโนมัติ

ผู้ใช้เลือก Render แผน Free สำหรับ Node.js 24+ ใน Docker และ Turso แผน Free สำหรับฐานข้อมูลออนไลน์ที่เข้ากับ SQLite ผู้ใช้ยอมรับว่า Render พักบริการหลังไม่มีคนใช้ 15 นาที เปิดใหม่อาจรอประมาณ 1 นาที และงานดึงข่าว/Push ไม่ทำงานระหว่างพัก โควตาฟรีอาจทำให้บริการหยุดตอบจนโควตากลับมา ไม่อ้างว่าฟรีแบบไม่จำกัดหรือมี uptime รับประกัน

ใช้ Superpowers brainstorming และ writing-plans, Taste app-screen rules, Impeccable Operate mode, Lucide, Simple Icons และ Playwright ผู้ใช้ไม่ได้เพิ่มกติกาไอคอนเฉพาะ

## แนวทาง

- Render แบบเสียเงินพร้อมดิสก์: รักษาไฟล์ SQLite ได้ตรงที่สุด แต่ไม่ตรงงบ 0 บาท
- Docker บนเครื่องผู้ใช้และ tunnel: ไม่มีค่าเช่า แต่ผู้ใช้ไม่สะดวกเปิดเครื่องค้างไว้
- Cloudflare Workers + D1: มีโควตาฟรี แต่ต้องย้าย runtime และส่วนบัญชีกว้างกว่าเดิม
- **แนวทางที่เลือก:** Render Free + Turso Free รักษา Node/Docker และ UI เดิม ปรับการเชื่อมฐานข้อมูลให้รองรับเครือข่ายและ Promise แทน SQLite แบบ synchronous

## ขอบเขตและระบบเดิม

ใช้ plain HTML/CSS/JavaScript, ภาษาไทย, ชื่อและโลโก้ StockLens, Inter/Noto Sans Thai และโทนน้ำเงินหม่นเดิม ไม่ย้าย framework ไม่เพิ่มข้อมูลการถือหุ้นหรือซื้อขาย รักษา HTTP API, cookie session, scrypt password hashes, recovery code, TOTP และการแยกข้อมูลแต่ละบัญชี

ฐานข้อมูลท้องถิ่นยังใช้สำหรับพัฒนาและทดสอบ ส่วนโฮสต์ฟรีต้องใช้ Turso โดยตรง ห้ามเก็บข้อมูลผู้ใช้ลงไฟล์ชั่วคราวบน Render และห้าม fallback ไปฐานข้อมูลว่างเมื่อ URL/token ผิดหรือเครือข่ายล้มเหลว

ปรับการเข้าฐานข้อมูลของ server, feeds, quotes, forecast, AI, Push, email verification และ login OTP ผ่าน database interface เดียว ทุกจุดที่ต้องอ่าน/เขียนข้อมูลเครือข่ายต้อง await ใช้ transaction ที่ผูกกับ connection/transaction handle ของ SDK จริง ไม่ส่ง BEGIN/COMMIT เป็นคำขอ HTTP แยกกันแล้วสมมติว่า atomic

## หน้าจอ

รักษาภาพจำเดิมและใช้พื้นที่ให้ทำงานได้มากขึ้น แยกตัวอักษรหัวข้อ เนื้อหา และข้อมูลรองให้ชัด ใช้สีหลักกับปุ่มหลักและตำแหน่งที่เลือก สีสถานะต้องมีข้อความ/สัญลักษณ์ประกอบ ตัวเลขจัดแนวได้ ไม่มีตัวเลข ข่าว หรือผล AI ที่แต่งขึ้นเพื่อเติมหน้าจอ

| หน้า | สิ่งที่ต้องเห็นและทำได้ก่อน |
| --- | --- |
| สมัคร/Login | ฟอร์ม ขั้นตอนกู้บัญชี และข้อผิดพลาดเด่น ลดภาพตัวอย่างที่ไม่มีข้อมูลจริง รักษารหัสกู้คืน/OTP/MFA |
| ภาพรวม | ข่าวที่เกี่ยวข้องกับบริษัทที่ติดตามมาก่อน ย่อคำแนะนำและตัวนับเป็นส่วนรอง ไม่มีบริษัทให้เห็นปุ่มเลือกบริษัท |
| ข่าว | หัวข้อ แหล่งต้นฉบับ เวลา และข้อมูลเก่าอยู่ใกล้กัน กรองข่าวและเปิดต้นฉบับได้ |
| สิ่งที่ติดตาม | รายชื่อและการเพิ่ม/นำออก ราคาต้องแสดงเวลาที่ได้ข้อมูล |
| ค้นหา | แยกค้นบริษัท ค้นข่าวย้อนหลัง และเปิด Google/Bing ภายนอกให้เข้าใจได้ |
| AI Insights | เลือกข่าว/บริษัท สรุปพร้อมอ้างอิง ถามต่อ และแนวโน้มทดลองเป็นคนละส่วน บอกเมื่อ key/ข้อมูลไม่พร้อม |
| แหล่งข้อมูล | แสดงว่ารายการใดเป็นฟีดจริงหรือบุ๊กมาร์ก ค้นหาและเปิด/ปิดรายการยาวได้ |
| บัญชี/แจ้งเตือน | แสดงความสามารถที่เปิดจริง ไม่บอกว่าส่งอีเมลหรือ Push สำเร็จเมื่อยังไม่ได้ส่ง |

Desktop ใช้ sidebar มีชื่อเมนูและพื้นที่ข่าวเด่น Tablet ปรับจำนวนคอลัมน์ตามเนื้อหา Mobile ใช้เมนูสั้นสำหรับภาพรวม ข่าว สิ่งที่ติดตาม และเพิ่มเติม หน้ารองเข้าถึงได้ครบ รองรับ focus/keyboard/safe-area และไม่มีแถบคงที่บังเนื้อหา

ทุกส่วนมีสถานะโหลด ไม่มีข้อมูล ผิดพลาด ข้อมูลเก่า และบริการไม่พร้อมตามความจำเป็น ข้อผิดพลาดจากเครือข่ายต้องไม่ล้างแบบฟอร์มหรือแสดงว่าบันทึกสำเร็จ การเปิดหลัง Render พักอาจแสดงหน้ารอของโฮสต์ก่อน JavaScript ของแอปเริ่ม จึงอธิบายข้อจำกัดนี้ในคู่มือด้วย

## ไอคอน

ใช้ Lucide SVG จริงสำหรับปุ่ม/เมนู ใช้ Simple Icons สำหรับแบรนด์ที่มีในชุด บริษัทที่ไม่มีใช้ ticker ไม่วาดโลโก้แบรนด์ขึ้นเอง เก็บเฉพาะ assets ที่ใช้พร้อมที่มา/ใบอนุญาตและเวอร์ชัน ไม่พึ่ง CDN ตอนรัน ปุ่มไอคอนต้องมีชื่อ accessible และไอคอนประกอบข้อความเป็น aria-hidden คงโลโก้ StockLens เดิม

ไฟล์ dist ใหม่ต้องเข้าถึงได้ผ่าน static allowlist ที่เจาะจง ห้ามเปิด static ทั้งรีโปเพื่อแก้ asset 404

## โฮสต์ฟรีและการตั้งค่า

Browser/PWA → Render HTTPS → Docker/Node หนึ่ง instance → Turso Cloud

- render.yaml ต้องระบุ plan: free ชัดเจน ไม่มี disk, cron แบบเสียเงิน, paid datastore หรือบริการ keep-alive เพื่อเลี่ยงการพักของโฮสต์
- HOST=0.0.0.0, PORT จากโฮสต์, APP_ORIGIN ตรงกับ URL HTTPS ที่ Render จัดให้ ไม่ซื้อโดเมน
- TURSO_DATABASE_URL และ TURSO_AUTH_TOKEN เป็น secrets ฝั่งเซิร์ฟเวอร์ เก็บ MFA/VAPID keys ให้คงเดิมข้าม deploy
- /api/health ตรวจฐานข้อมูลจริงก่อนส่ง ready ไม่รายงานว่าปกติเมื่อ Turso ใช้ไม่ได้
- ตรวจ reverse-proxy IP จาก topology จริงก่อนเปิด trust ไม่เชื่อ X-Forwarded-For ตัวแรกโดยอัตโนมัติ และมี regression test สำหรับการปลอม header
- Login rate limits สำคัญต้องไม่หายเพียงเพราะ process ถูกพัก/เริ่มใหม่ และการทดสอบต้องครอบคลุมผู้ใช้หลายคนหลัง proxy เดียวกัน
- Render Free บล็อกพอร์ต SMTP ทั่วไป จึงตั้ง EMAIL_LOGIN_OTP_ENABLED=false ใน deploy นี้และแสดงว่าอีเมลไม่พร้อม รักษา SMTP สำหรับ local/โฮสต์ที่รองรับ หากเพิ่ม email ผ่าน HTTPS provider ให้เป็นงานที่เสนอแยก ไม่เปิดบริการเพิ่มโดยไม่จำเป็น
- AI ใช้ key ในโควตาฟรีเมื่อผู้ใช้ตั้งไว้ Ollama บนคอมผู้ใช้ไม่ได้ตามขึ้นโฮสต์ กรณีไม่มี AI/ราคา/ข่าวเสริมให้แสดง unavailable อย่างถูกต้อง
- Push และรอบดึงข่าวทำงานได้เฉพาะระหว่าง service ทำงาน ไม่รับประกันการแจ้งเตือนต่อเนื่องเมื่อ Render พัก

## ข้อมูลเดิมและ backup

ฐานข้อมูลจริงบนเครื่องผู้ใช้ไม่ได้ถูกย้ายอัตโนมัติ ต้องมีวิธีย้ายสำเนาที่รักษารหัสผ่านที่ hash แล้ว รายการติดตาม และคีย์ MFA เดิม โดยไม่ส่ง credentials/ข้อมูลบัญชีในแชตหรือ Git ขั้นตอน import เป็นคำสั่งแยกที่ใช้กับเป้าหมายว่างและตรวจความครบถ้วนก่อนเปิดใช้งาน ห้าม overwrite ฐานข้อมูล Turso ที่มีผู้ใช้แล้ว

การ restore ต้องมีขั้นตอนเพิกถอน sessions เก่าที่อาจกลับมาจาก backup แยกสำเนาทดสอบออกจากข้อมูลจริง Local ใช้ SQLite online backup ต่อได้ Remote ใช้ export/backup ของ Turso ไปยังที่เก็บที่ผู้ใช้ควบคุม ไม่ฝากสำเนาสำคัญไว้บนไฟล์ชั่วคราวของ Render รายงานจะบอกชัดว่ามีข้อมูลเดิมให้ย้ายหรือเริ่มบริการใหม่

## การตรวจรับ

1. Unit/API ครอบคลุมทั้งฐานข้อมูล local และ driver เครือข่าย พร้อม fault injection: timeout, token ผิด, commit ล้มเหลว, คำขอซ้ำ และ optimistic revision conflict
2. สมัคร/Login/Logout/recovery/TOTP/OTP/ลบบัญชีและข้อมูลแยกบัญชีผ่านชุดเดิมหลัง async refactor; token ครั้งเดียวต้องใช้พร้อมกันสำเร็จได้ไม่เกินหนึ่งคำขอ
3. Playwright ตรวจ flow ข่าว ติดตาม ค้นหา AI บัญชี และ PWA ที่ 390, 768, 1440px ไม่มี horizontal overflow เมนูและ dialog ใช้ keyboard ได้ เก็บภาพก่อน/หลังจากแอปจริง
4. Docker build/start ผ่าน และ credentials/config เข้า runtime โดยไม่มี secrets ใน image/log/HTML; Compose local ยังรันได้
5. CI เพิ่ม browser suites research/security/login ที่เกี่ยวข้อง และทดสอบต่อฐานข้อมูลเครือข่ายภายใน CI ที่แยกจาก production ไม่ใช้ secret production ทดสอบ
6. ข้อมูลบัญชีและสิ่งที่ติดตามยังอยู่หลัง restart/redeploy โดย cloud ใช้ remote database เดิม ไม่ใช้ local file เป็นหลักฐานแทน
7. รายงานว่าออนไลน์เมื่อ deploy สำเร็จและตรวจ HTTPS, health, สมัคร/Login และการคงอยู่ของข้อมูลบนโฮสต์แล้วเท่านั้น

## สิ่งที่ต้องให้ผู้ใช้ทำภายหลัง

เชื่อม Render และสร้าง/เชื่อม Turso แผนฟรี โดยใส่ secrets ใน dashboard หรือช่องทาง credential ที่เหมาะสมเท่านั้น ไม่มี Turso plugin ในเครื่องมือที่ค้นพบตอนทำแบบ จึงอาจต้องให้เจ้าของบัญชีทำขั้นตอนสร้างฐานข้อมูล/ตั้ง token ผ่าน dashboard เอง ระหว่างนั้นพัฒนาและทดสอบด้วยฐานข้อมูลแยกได้

หากมีบัญชีเดิมที่ต้องรักษา ต้องจัดเตรียม backup/คีย์ผ่านช่องทางที่เหมาะสมก่อน cutover ห้ามถือว่าไม่มีข้อมูลเดิมจากการที่ workspace ไม่มี .data

ค่าใช้จ่ายอนุญาตเป็นศูนย์เท่านั้น การอนุมัติแบบไม่อนุญาตการเพิ่ม plan หรือ overages การ merge และเปิดบริการจะยืนยันจาก diff/การตั้งค่าจริงตามขอบเขตที่ยังไม่ได้รับอนุญาต ผู้พัฒนาตัดสินใจรายละเอียด CSS โครงสร้างไฟล์ และ tests ภายในแบบนี้ได้

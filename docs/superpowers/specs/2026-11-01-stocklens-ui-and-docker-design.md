# StockLens — แบบปรับหน้าจอและเปิดออนไลน์ด้วย Docker

วันที่: 1 พฤศจิกายน 2026  
สถานะ: ร่างสำหรับตรวจแบบ ยังไม่ได้อนุมัติให้เริ่มพัฒนา  
รีโป: https://github.com/lew280352-sudo/temp

## เป้าหมายและสิ่งที่ตกลงแล้ว

ผู้ใช้เลือกให้ปรับแอปเดิมและนำขึ้นโฮสต์ Docker ที่มีดิสก์ถาวร ใช้ระบบบัญชีและ SQLite เดิมต่อ โดยใช้ Superpowers brainstorming, design-taste-frontend, Impeccable, Lucide, Simple Icons และ Playwright ไม่มีข้อกำหนดไอคอนเพิ่มเติมจากผู้ใช้

ข้อกำหนดเพิ่มล่าสุด: ไม่ใช้บริการแบบเสียเงิน ไม่เช่าโฮสต์ ไม่ซื้อโดเมน และไม่เปิด API แบบคิดค่าใช้จ่าย ต้องเสนอวิธีฟรีพร้อมข้อจำกัดจริงก่อนเริ่มพัฒนา แผน Render แบบเสียเงินในร่างก่อนหน้านี้ถูกยกเลิก

StockLens เป็นเว็บภาษาไทยสำหรับผู้ติดตามข่าวบริษัทสหรัฐฯ งานหลักคือดูว่าบริษัทที่ติดตามมีข่าวอะไรใหม่ เปิดแหล่งต้นทาง และขอสรุปข่าวด้วย AI เมื่อมีบริการพร้อมใช้งาน ความสำเร็จคือใช้งานบนคอมและมือถือได้จาก URL HTTPS ที่คงที่ และข้อมูลบัญชี/สิ่งที่ติดตามยังอยู่หลัง restart หรือ deploy ใหม่

## แนวทางที่พิจารณา

1. ปรับ HTML/CSS/JavaScript เดิม ใช้ Node.js 24+, Docker และ SQLite บนดิสก์ถาวร: ใช้ระบบบัญชีเดิมต่อได้ งานย้ายระบบน้อย และต้องใช้เซิร์ฟเวอร์หนึ่ง instance
2. ย้าย backend ขึ้น Sites/Workers และฐานข้อมูลใหม่: ได้ระบบโฮสต์อีกแบบ แต่ต้องเปลี่ยนส่วน SQLite, SMTP และงาน background เป็นงานย้ายระบบที่กว้างกว่า

ผู้ใช้เลือกแนวทาง 1 แล้ว รายละเอียดภาพและผู้ให้บริการโฮสต์ด้านล่างเป็นข้อเสนอของผู้พัฒนาเพื่อให้ตรวจแบบ

## ขอบเขตงาน

- ปรับหน้าสมัคร/Login, ภาพรวม, ข่าว, สิ่งที่ติดตาม, ค้นหาบริษัท, AI Insights, แหล่งข้อมูล และการตั้งค่าบัญชี/การแจ้งเตือน
- ใช้ plain HTML/CSS/JavaScript และ Node API เดิม ไม่เพิ่ม framework หรือเปลี่ยนโมเดลข้อมูลบัญชี
- จัดระบบไอคอน แก้ความอ่านง่าย การใช้คีย์บอร์ด และโครงสร้างมือถือ
- เตรียมไฟล์โฮสต์ Docker, การตั้งค่า HTTPS, ดิสก์, health check และคู่มือดูแลระบบ
- ทดสอบหน้าจอและการทำงานด้วย Playwright และชุดทดสอบ API/บัญชีเดิม
- เปิด HTTPS ด้วยวิธีฟรีเมื่อยืนยันเครื่องที่ใช้รันและเชื่อมบัญชีบริการที่จำเป็นแล้ว ไม่สร้างบริการแบบเสียเงิน

งานนี้ไม่เพิ่มการซื้อขายหุ้น ไม่เปลี่ยนรายการติดตามเป็นข้อมูลพอร์ต ไม่สร้างราคาหรือผลทำนายจำลอง และไม่สัญญาว่าฟีเจอร์ที่ต้องใช้ API key, SMTP หรือ Push จะทำงานก่อนมีบริการเหล่านั้นจริง

## ทิศทางภาพและหน้าจอ

ใช้โหมด Operate ของ Impeccable และ app-screen rules ของ Taste: ผู้ใช้มาอ่านข่าวและทำงาน โครงสร้างที่คุ้นเคย ความอ่านง่าย และข้อมูลจริงมีความสำคัญกว่าการตกแต่ง

เก็บชื่อและโลโก้ StockLens, น้ำเงินหม่น, Inter และ Noto Sans Thai เดิมไว้ ปรับตัวอักษรรองให้มี contrast ที่อ่านได้ ใช้สีหลักกับปุ่มหลักและตำแหน่งที่เลือก ส่วนสีสถานะใช้กับความหมายที่ชัดเจน ตัวเลขและวันที่จัดให้อ่านเทียบกันได้ ไม่มีการเคลื่อนไหวตกแต่งหรือหน้าโหลดที่ต้องรอดู animation

หน้าจอคอมใช้ sidebar ที่มีชื่อเมนูและพื้นที่อ่านข่าวเป็นส่วนหลัก ที่ความกว้างกลางปรับจำนวนคอลัมน์ตามเนื้อหา มือถือใช้แถบนำทางสั้นสำหรับภาพรวม ข่าว สิ่งที่ติดตาม และเมนูเพิ่มเติม หน้ารองยังเข้าถึงได้ครบ ไม่ยัดเมนูทั้งหมดลงในแถวเดียว ต้องรองรับ keyboard, focus, safe area และไม่มีแถบคงที่บังเนื้อหา

| ภาพรวม | บริษัทที่ติดตามมีข่าวอะไรใหม่ | ให้ข่าวล่าสุดที่เกี่ยวข้องมาก่อน ย่อคำแนะนำและจำนวนบริษัท/แหล่งข่าวเป็นข้อมูลรอง มีทางไปเลือกบริษัทเมื่อยังไม่ติดตาม |

| บัญชี/แจ้งเตือน | ตั้งค่าอะไรได้จริงบนอุปกรณ์นี้ | แยกค่าในแอป ความสามารถของเบราว์เซอร์ และบริการฝั่งเซิร์ฟเวอร์ ไม่แสดงว่าส่งอีเมล/Push สำเร็จเมื่อไม่ได้ส่งจริง |

ทุกส่วนมีสถานะ loading, ไม่มีข้อมูล, error, ข้อมูลเก่า และสำเร็จตามที่เกี่ยวข้อง รักษาข้อมูลในฟอร์มเมื่อคำขอล้มเหลว ไม่ใช้ข้อมูลปลอมเติมพื้นที่ว่าง

## ไอคอนและโลโก้

- Lucide ใช้กับเมนู ปุ่ม และสถานะทั่วไป โดยเลือกจากชุดจริงและบันทึกที่มา/ใบอนุญาต เก็บเฉพาะ SVG ที่ใช้ในแอป ไม่โหลดทั้งชุดจาก CDN
- ไอคอนข้างข้อความเป็นของตกแต่งสำหรับ screen reader ปุ่มที่มีแต่ไอคอนต้องมีชื่อที่เข้าถึงได้ ใช้ขนาดและ stroke สม่ำเสมอ
- Simple Icons ใช้กับแบรนด์บริษัทที่มีไอคอนเหมาะสมและตรวจชื่อได้ บริษัทที่ไม่มีในชุดใช้ ticker เป็นข้อความแทน ไม่ประดิษฐ์โลโก้แบรนด์ขึ้นเอง
- โลโก้ StockLens เป็นอัตลักษณ์ของแอปและใช้ต่อได้ จัดทำรายการที่มาและใบอนุญาตของ assets
- ถ้าเพิ่มไฟล์ใหม่ใน dist ต้องเพิ่มใน static asset allowlist ของ server โดยไม่เปิดให้เข้าถึงไฟล์ทั้งรีโป

## สถาปัตยกรรมออนไลน์

Browser/PWA → HTTPS ของโฮสต์ → Node.js 24+ ใน Docker หนึ่ง instance → SQLite บน persistent disk

ข้อเสนอใหม่สำหรับการใช้งานส่วนตัวโดยไม่เช่าโฮสต์: รัน Docker บนเครื่องของผู้ใช้ เก็บ SQLite ใน named volume บนดิสก์ของเครื่อง แล้วเปิด HTTPS ผ่าน Tailscale Funnel ซึ่งใช้กับแผน Personal ฟรีได้ ไม่ต้องซื้อโดเมน ทั้งนี้ผู้ใช้ยังไม่ได้ยืนยันว่าจะเปิดเครื่องและเชื่อมอินเทอร์เน็ตไว้ได้หรือไม่ จึงยังไม่ถือว่าเลือกวิธีนี้แล้ว

ข้อจำกัดที่ต้องยอมรับก่อนเลือก: เว็บและ Push จะทำงานเฉพาะเมื่อเครื่อง Docker และ tunnel ทำงาน เครื่องปิดหรือหลับจะเข้าเว็บไม่ได้ ยังมีค่าไฟและอินเทอร์เน็ตของเครื่องตามการใช้งาน Tailscale Funnel ยังเป็น beta และมีข้อจำกัด bandwidth ไม่รับรอง uptime แบบบริการโฮสต์ที่มีสัญญา

ใช้ชื่อ HTTPS ภายใต้ .ts.net ที่บริการจัดให้โดยไม่ซื้อโดเมน และรักษาชื่อเครื่อง/เครือข่ายเดิมเพื่อให้ URL ต่อเนื่อง Cloudflare Quick Tunnel เป็นทางเลือกสำหรับทดลองชั่วคราว แต่ URL เปลี่ยนเมื่อเริ่มใหม่ จึงไม่ใช้แทน URL ถาวรโดยไม่แจ้ง

ไม่ใช้ Render Free กับ SQLite จริง เพราะไฟล์ฐานข้อมูลไม่คงอยู่หลัง restart/redeploy และแนบดิสก์ถาวรไม่ได้ หากผู้ใช้ไม่สะดวกเปิดเครื่อง จะประเมินโฮสต์ฟรีหรือการปรับ backend ที่อยู่ในโควตาฟรีใหม่ก่อนเปลี่ยนสถาปัตยกรรม

### ค่าที่ต้องตรวจใน runtime

- ใน container ใช้ HOST=0.0.0.0, PORT=4173; Compose ผูกพอร์ตกับ loopback ของเครื่องตามเดิม และ APP_ORIGIN ตรงกับ HTTPS URL ของ tunnel
- DATABASE_PATH=/app/.data/stocklens.sqlite และ mount persistent disk ที่ /app/.data
- ตรวจสิทธิ์เขียนไฟล์ภายใต้ UID ของ node เมื่อ mount volume ใหม่ โดยยังให้แอปรันเป็นผู้ใช้ node ไม่แก้ด้วยการเปิดสิทธิ์กว้างให้ทุกคนเขียนได้
- Health check ใช้ /api/health ที่มีอยู่และทดสอบการเปิดฐานข้อมูลจริง
- API keys, MFA encryption key, VAPID และ SMTP อยู่ใน secret/environment ของโฮสต์ ไม่อยู่ใน Git, image หรือ JavaScript ฝั่งเบราว์เซอร์
- ตรวจ rate limiting หลัง proxy แก้การรวมผู้ใช้ทุกคนไว้ใน socket IP เดียวด้วยการตั้งค่าที่ระบุขอบเขต proxy ชัดเจน ต้องมี test ปฏิเสธ forwarded headers จากแหล่งที่ไม่เชื่อถือ ไม่ใช้ X-Forwarded-For ตัวแรกโดยตรง
- AI ออนไลน์ใช้เฉพาะโควตาฟรีเมื่อมี key และไม่เปิด billing อัตโนมัติ; Ollama ในเครื่องใช้ได้หากเครื่องมีทรัพยากรพอและ container เข้าถึงได้ ต้องแสดงว่า fallback ไม่พร้อมเมื่อเชื่อมไม่ได้ ไม่เปิด Ollama สู่สาธารณะเพื่อแก้ปัญหานี้

## ข้อมูลเดิมและสำรองข้อมูล

รักษา schema และพฤติกรรมบัญชีเดิม การ deploy ครั้งแรกไม่ได้ย้ายฐานข้อมูลบนเครื่องผู้ใช้อัตโนมัติ หากต้องเก็บบัญชีเดิม ให้สำรองด้วย SQLite online backup และย้ายสำเนาพร้อมคีย์ MFA/VAPID ผ่านช่องทางลับที่เหมาะสมก่อนเปิดบริการ ห้ามขอให้แปะฐานข้อมูลหรือคีย์ลับในแชต

ปรับ backup script ให้กำหนดปลายทางได้ สำหรับโฮสต์ตั้งให้เก็บสำเนาใต้ persistent disk และบันทึกวิธีนำสำเนาออกนอกเครื่อง สำเนาบนดิสก์เดียวช่วยกู้จากการแก้ข้อมูลผิด แต่ไม่ทดแทน backup นอกบริการ ต้องทดสอบ restore กับฐานข้อมูลแยกก่อนนำมาใช้จริง

## การตรวจรับ

1. บัญชีเดิมและ flow สมัคร/Login/Logout/recovery/OTP/MFA/ลบบัญชีผ่าน regression tests โดยใช้ฐานข้อมูลทดสอบ
2. Playwright ตรวจเส้นทางข่าว ติดตาม ค้นหา AI และตั้งค่าบนจอ 390, 768 และ 1440px ไม่มี horizontal overflow; เมนู focus และปุ่มสำคัญใช้คีย์บอร์ดได้
3. ตรวจ empty/loading/error/stale และบริการที่ยังไม่ใส่ key ไม่มีหน้าที่แสร้งว่ามีข้อมูลหรือส่งแจ้งเตือนแล้ว
4. Docker build และเริ่มแอปได้ ส่ง environment เข้า runtime ได้จริง และใช้ฐานข้อมูลบน volume หลัง restart/recreate ได้
5. CI รัน unit/API และ browser suites ที่เกี่ยวข้อง รวม research, security และ email-login UI เมื่อแก้หน้าจอเหล่านั้น พร้อม container smoke test
6. เก็บภาพก่อน/หลังจากแอปที่รันจริง ไม่ใช้ภาพร่างเป็นหลักฐานว่าฟังก์ชันทำงานแล้ว
7. ก่อนรายงานว่าออนไลน์ ต้องได้สถานะ deploy สำเร็จและตรวจ URL HTTPS, /api/health, สมัคร/Login, การอ่านข่าว และความคงอยู่ของข้อมูลจริงบนโฮสต์

## สิ่งที่ยังต้องมีจากบัญชีผู้ใช้

- ยืนยันว่าเปิดเครื่อง Docker และอินเทอร์เน็ตค้างไว้ได้หรือไม่ ก่อนเลือกการเปิดเว็บผ่าน tunnel บนเครื่องนั้น
- เชื่อมบัญชี Tailscale Personal ฟรีหากเลือก Funnel ไม่เปิดแผนเสียเงินหรือสมัครทดลองที่เปลี่ยนเป็นเสียเงินอัตโนมัติ
- ใส่คีย์บริการผ่าน secret ของโฮสต์เพื่อเปิด AI/ราคา/ข่าวเพิ่มเติม และตั้ง SMTP หากต้องการ email OTP จริง
- หากต้องการย้ายบัญชีที่ใช้อยู่ ต้องมี backup และคีย์เดิมผ่านช่องทางที่ปลอดภัย; จะไม่เลือกเริ่มฐานข้อมูลว่างแทนข้อมูลเดิมโดยไม่แจ้ง

ผู้พัฒนาตัดสินใจรายละเอียด CSS, การจัดไฟล์, ไอคอนแต่ละปุ่ม และวิธี regression tests ได้ภายในขอบเขตนี้ ไม่ต้องขออนุมัติซ้ำสำหรับการแก้ให้ตรงแบบ การ merge และเปิดบริการจะขอคำยืนยันกับ diff และการเปิดให้เข้าถึงจริงตามขอบเขตที่ยังไม่ได้รับอนุญาต ขอบเขตค่าใช้จ่ายเป็นศูนย์และไม่อนุญาตให้สร้างบริการเสียเงิน
